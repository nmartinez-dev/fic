# Documentación — Cordillera

Material de apoyo al código y a la entrega de la prueba técnica. El
[README del repo](../README.md) cubre arranque local, usuarios de prueba, stack
resumido y la demo en [fic-admin.vercel.app](https://fic-admin.vercel.app/).

---

## Cómo leer la documentación

| Documento | Audiencia | Cuándo usarlo |
| --- | --- | --- |
| [**arquitectura.md**](arquitectura.md) | Desarrollo | Stack, capas, datos, flujos, deploy y variables de entorno |
| [**criterios-y-decisiones.md**](criterios-y-decisiones.md) | Producto / revisión | Enfoque, scope, criterios de priorización y mapa del PDF |
| [**bitacora/**](bitacora/) | Producto | Evolución feature a feature: qué se hizo y qué quedó pendiente |
| [`prueba-tecnica-fde.pdf`](prueba-tecnica-fde.pdf) | Referencia | Enunciado original del cliente |

**Arquitectura** responde *cómo funciona*. **Criterios y decisiones** responde
*qué entregamos, por qué y cómo abordamos cada problema del PDF* (incluidos los
que quedaron fuera del menú). **Bitácora** responde *cómo fue avanzando cada
módulo* en el tiempo.

No hay solapamiento obligatorio: conviene empezar por criterios si evaluás la
entrega; por arquitectura si vas a modificar código; por bitácora si querés el
detalle narrativo de una feature concreta.
